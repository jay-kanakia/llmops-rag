<details><summary><b>View Test Case Data</b></summary>

- **Input:** How does query-vector similarity search differ from chunk-vector retrieval, and what do both return?
- **Actual Output:** Query-vector similarity search
- You convert the user query into a query vector (using the same embedding model that made the stored vectors).
- That query vector is compared (similarity search) against the chunk vectors in the vector DB (they must share the same dimensional space).
- It returns the top‑K most similar chunk vectors (e.g., 4) — i.e., the stored vectors that are closest to the query.

Chunk-vector retrieval
- These are the stored vectors that represent text chunks (created earlier from your documents).
- Retrieval returns those chunk vectors (numbers), but each chunk vector has metadata that contains the original text.
- After retrieval you extract the original text from metadata and assemble those chunks into the retrieved context (which you then pass to the LLM for augmentation).

In short: the query-vector is what you use to search; chunk-vectors are what you search over. The search operation returns chunk vectors (numbers), and—via metadata—returns the original text chunks you actually use.
- **Expected Output:** Query-vector similarity search uses the **query converted into a vector** and searches the vector database for the **most similar chunk vectors**.  
Chunk-vector retrieval returns the **matching vectors**, and then their **original text chunks** are extracted from metadata and combined into the retrieved context.

So:
- **Similarity search** = finds similar vectors
- **Retrieval** = gives back the related original text chunks/context

</details>

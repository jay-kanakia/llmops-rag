<details><summary><b>View Test Case Data</b></summary>

- **Input:** How does query-vector similarity search differ from chunk-vector retrieval, and what do both return?
- **Actual Output:** Query-vector similarity search is the search operation: you convert the user query into a query vector (using the same embedding model and dimensional space) and compare it against chunk vectors in the vector DB to find nearest neighbors. It returns the top-N similar chunk vectors (numeric vectors, usually with IDs and similarity scores).

Chunk-vector retrieval is what you do with those results: you fetch the matched chunk vectors and (importantly) their stored metadata. From the metadata you extract the original text chunks and assemble them into a single retrieved context. So both steps initially return vectors/numeric results, but retrieval gives you access to the original text (via metadata) which you then combine and pass to the LLM.
- **Expected Output:** Query-vector similarity search uses the **query converted into a vector** and searches the vector database for the **most similar chunk vectors**.  
Chunk-vector retrieval returns the **matching vectors**, and then their **original text chunks** are extracted from metadata and combined into the retrieved context.

So:
- **Similarity search** = finds similar vectors
- **Retrieval** = gives back the related original text chunks/context

- Optionally downsample thumbs-up or clearly satisfied conversations (they’re low yield for hallucination detection).

Example allocation for 1,000 evaluations:
- 250 random conversations (baseline)

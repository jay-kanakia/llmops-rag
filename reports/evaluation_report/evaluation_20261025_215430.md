- **Actual Output:** - Query-vector similarity search
  - What it is: you convert your text query into a query vector (using the same embedding model/dimensional space as your chunks) and run a similarity search in the vector DB.
  - What it returns initially: the top-N most similar chunk vectors (numerical vectors — e.g., "4 vectors similar to my query").  
  - Note: those vectors are returned because they live in the same embedding space (same dimensions) as the chunks.

- Chunk-vector retrieval
  - What it is: taking those retrieved vectors and loading the stored metadata associated with them (you stored the original text with each chunk/vector).
  - What it returns: the original text chunks pulled from metadata, which you can combine/assemble into one complete "retrieved context" to feed the LLM (this is the retrieval output used for augmentation).

In short: the similarity search finds and returns numeric nearest-neighbor vectors; chunk retrieval maps those vectors to their stored metadata and returns the original text chunks (assembled into the retrieved context).
- **Expected Output:** Query-vector similarity search uses the **query converted into a vector** and searches the vector database for the **most similar chunk vectors**.  
Chunk-vector retrieval returns the **matching vectors**, and then their **original text chunks** are extracted from metadata and combined into the retrieved context.

So:
- **Similarity search** = finds similar vectors
- **Retrieval** = gives back the related original text chunks/context

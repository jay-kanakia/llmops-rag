<details><summary><b>View Test Case Data</b></summary>

- **Input:** How does query-vector similarity search differ from chunk-vector retrieval, and what do both return?
- **Actual Output:** Query-vector similarity search is the act of converting your query into a vector (using the same embedding model as the chunks so they live in the same dimensional space) and searching the vector database for nearest neighbors. That step returns the top similar vectors — i.e., numbers representing the closest chunks.

Chunk-vector retrieval is the follow-up where you use those retrieved vectors to load the original text stored in their metadata. That step returns the actual text chunks (which you can combine/assemble into one retrieved context) that you then attach to your query for augmentation and pass to the LLM.

In short:
- Similarity search returns top similar vectors (numbers).  
- Chunk retrieval returns the original documents/text (via metadata), which you assemble into the retrieved context.
- **Expected Output:** Query-vector similarity search uses the **query converted into a vector** and searches the vector database for the **most similar chunk vectors**.  
Chunk-vector retrieval returns the **matching vectors**, and then their **original text chunks** are extracted from metadata and combined into the retrieved context.

So:
- **Similarity search** = finds similar vectors
- **Retrieval** = gives back the related original text chunks/context

</details>
